The local verification passed 356 Rust and 474 Swift tests. In the offline Codex → Switchyard → LiteLLM check, the session ID stayed stable across two turns in one conversation and differed in a new conversation. A live check of the installed local build matched both observed Codex IDs to the headers received by LiteLLM.

### Prompt cache A/B test

On `gpt-6-luna`, we ran six pairs of series (36 requests total) through the same LiteLLM gateway with `x-litellm-session-id` enabled or disabled. Each series repeated the same prompt three times and used a unique prefix marker to limit cache sharing. We measured warm-up as the change in cached input token share from the first request to the average of the two repeats.

Across the five pairs where both series started at 0% cache hits, forwarding the header improved that measure by **95.0 percentage points** (2.1% without the header versus 97.2% with it on repeats). In the sixth pair, the first request without the header unexpectedly had a 97.1% cache hit share and both repeats had 0%. We report that pair separately because its starting cache was already warm.
